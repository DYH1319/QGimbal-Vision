# 矩形检测模块实现与精度分析

> 汇报人：开发组  
> 项目：QGimbal-Vision  
> 日期：2026-08-14  
> 环境：Raspberry Pi / OpenCV 4.10.0 / USB Camera 640×480@60fps

## 1. 模块职责

`vision/rect_detect.py` 负责在 BGR 视频帧中检测矩形目标，输出矩形中心点 `(cx, cy)`、角点 `box` 与面积 `area`，供 `main.py` 中的 PID 控制环使用。

## 2. 实现流程

`detect_rectangles()` 采用传统 CV 管线：

1. **灰度化**：`cv2.cvtColor(frame, COLOR_BGR2GRAY)`
2. **高斯模糊**：`3×3` 核，轻微降噪
3. **大津法二值化**：`THRESH_BINARY + THRESH_OTSU`，自动适应全局亮度
4. **形态学处理**：`5×5` 矩形核，先 **开运算** 再 **腐蚀一次**
5. **Canny 边缘检测**：阈值 `25 / 75`
6. **轮廓提取**：`cv2.findContours(RETR_EXTERNAL, CHAIN_APPROX_SIMPLE)`
7. **多边形逼近**：`approxPolyDP(contour, 0.02 * perimeter, True)`
8. **矩形判定**：
   - 凸四边形
   - 四个内角均在 `90° ± angle_tol` 内（默认 `25°`）
   - 长边 / 短边 ≤ `3`
   - 面积在 `[min_area_ratio, max_area_ratio]` 之间（默认 `0.005 ~ 0.5`）
9. **排序输出**：按面积降序，取最大矩形作为追踪目标

核心代码见 `vision/rect_detect.py:34-106`。

## 3. 关键参数与默认值

| 参数 | 默认值 | 含义 | 影响 |
|------|--------|------|------|
| `min_area_ratio` | `0.005` | 最小面积占画面比例 | 低于此值的目标被丢弃 |
| `max_area_ratio` | `0.5` | 最大面积占画面比例 | 过滤过大的前景 |
| `angle_tol` | `25.0°` | 角点偏离直角的容差 | 允许轻微透视畸变 |
| `approxPolyDP` 精度 | `0.02 * 周长` | 轮廓逼近精度 | 影响角点数量与噪声敏感 |
| Canny 阈值 | `25 / 75` | 边缘提取阈值 | 较低阈值，保留弱边缘 |

在 `main.py:262` 中按以下参数调用：

```python
rects = detect_rectangles(frame, min_area_ratio=0.005, max_area_ratio=0.5, angle_tol=25.0)
```

## 4. 精度测试方法

为排除环境光与相机标定影响，采用合成数据在真实运行环境中测量：

- 构建 `640×480` 纯色背景，绘制不同尺寸、角度、长宽比的白色矩形；
- 叠加高斯噪声、模糊、复杂背景干扰；
- 调用 `detect_rectangles()`，对比检测结果与真实值；
- 记录中心误差、角度误差、面积误差与单帧耗时。

相机实际参数通过 `v4l2-ctl` 与 OpenCV 确认：

- 后端：V4L2
- 分辨率：`640×480`
- 帧率：`60.5 fps`

## 5. 精度结果

### 5.1 中心定位精度

中心点取四个角点均值，**亚像素级精度**，误差主要来自像素网格量化：

| 测试项 | 中心误差 (px) |
|--------|--------------|
| 200×100 轴对齐 | 0.50 |
| 120×80 轴对齐 | 0.50 |
| 120×80 旋转 45° | 0.71 |
| 120×80 旋转 89° | 1.12 |

> 结论：对追踪控制而言，中心定位精度已足够，误差主要来自角点的像素坐标取整，而非算法本身。

### 5.2 角度精度

| 旋转角度 | 角度误差 |
|----------|----------|
| 0° / 15° / 30° / 60° | < 0.3° |
| 45° | 0.72° |
| 89° | 0.99° |

方向检测精度较高，但追踪控制仅使用中心点，方向信息当前未用于闭环。

### 5.3 面积精度

形态学 `开运算 + 腐蚀` 会侵蚀白色区域边界，导致检测面积 **系统性低估 10% ~ 22%**：

| 测试项 | 面积误差 |
|--------|----------|
| 200×100 | -7.4% |
| 120×80 | -10.2% |
| 80×60 | -14.1% |
| 60×40 | -19.9% |

> 影响：对 PID 跟踪无影响；若未来用面积估算距离，需做标定补偿。

### 5.4 最小可检测尺寸

代码中 `min_area_ratio=0.005` 对应 `640×480` 下理论阈值 `1536 px`，但腐蚀导致实际可检测面积更大：

| 绘制面积 | 检测结果 |
|----------|----------|
| 2500 px | 通过 |
| 2000 px | 通过，但检测面积已降至 1565 px |
| 1600 px | **失败** |

> 实际可靠最小目标约为 **2000 ~ 2500 px**（占画面 0.65% ~ 0.82%）。这是当前算法最主要的限制。

### 5.5 长宽比限制

| 尺寸 (长×宽) | 长宽比 | 检测结果 |
|--------------|--------|----------|
| 160×60 | 2.67 | 通过 |
| 192×50 | 3.84 | 失败 |

代码中长宽比上限为 `3`，与测试结果一致。强透视或细长目标会被过滤。

### 5.6 鲁棒性

| 场景 | 结果 |
|------|------|
| 高斯噪声 σ = 5~30 | 全部通过 |
| 高斯模糊 3×3 / 5×5 / 7×7 | 全部通过 |
| 亮度 50~250 低对比度 | 全部通过 |
| 复杂背景 + 20 个干扰圆 | 通过 |
| 非矩形平行四边形（内角 63.4° / 116.6°） | 失败 |

Otsu + Canny + 形态学的组合对亮度、噪声、模糊表现出良好鲁棒性，但对强透视畸变或非矩形四边形较敏感。

### 5.7 性能

- 单帧检测耗时：`2.3 ~ 2.7 ms`
- 占 60fps 时间预算：约 15%
- 结论：检测本身不构成实时性瓶颈；瓶颈更可能来自 `cv2.imshow` 与串口交互。

## 6. 像素精度 → 实际角度精度换算

假设摄像头水平视场角（HFOV）为常见值 `60°`：

- 单像素视角：`60° / 640 ≈ 0.094°`
- 中心定位 0.5 px 误差：`0.5 × 0.094° ≈ 0.047°`

`main.py:266` 中 `target_center` 默认在画面中心右侧偏移 10 px：

```python
tracker.target_center = (frame.shape[:2][1] // 2 + 10, frame.shape[:2][0] // 2)
```

对应固定视角偏置约 `10 × 0.094° ≈ 0.94°`，用于将激光点与目标中心对齐。

## 7. 主要问题与优化建议

### 7.1 最小可检测面积偏低（当前最大风险）

- 建议：将 `min_area_ratio` 下调至 `0.002` 或改用绝对面积阈值；
- 若噪声增加，可减少一次额外腐蚀，或使用 `closing` 替代部分 `opening + erode`。

### 7.2 面积低估影响距离估计

- 建议：对已知尺寸目标建立“检测面积—真实面积”标定表；
- 或在 `DetectedRect` 中增加最小外接矩形面积作为备选字段。

### 7.3 缺乏帧间跟踪

- 建议：引入卡尔曼滤波或质心跟踪器，在短暂丢目标时预测位置，配合 `lost_timeout_s` 减少云台抖动。

### 7.4 未利用颜色信息

- 若目标始终为白色，可在 HSV / Lab 空间先做白色预过滤，再执行边缘检测，提高复杂背景下的抗干扰能力。

### 7.5 分辨率可提升

- 若 USB 带宽允许，可将采集分辨率提升至 `1280×720`，让远距离目标在画面中占据更多像素；
- 代价是帧率可能从 60fps 降至 30fps。

## 8. 结论

`vision/rect_detect.py` 基于 OpenCV 传统算法，实现简单、速度快、中心定位精度高，能够满足 QGimbal 目标追踪的精度需求。其主要限制在于 **最小可检测面积较大**，在远距离或目标较小时容易漏检；同时缺乏帧间跟踪，目标短暂丢失时会导致云台抖动。

当前阶段建议优先：**降低 `min_area_ratio` 并加入帧间预测**，以提升实际使用中的稳定性。
